## ADDED Requirements

### Requirement: SKILL.md contains complete questionnaire logic
The `composeDesignMdSkill()` function SHALL emit a SKILL.md that contains a 5-question interactive questionnaire section with dimension mapping rules for each answer.

#### Scenario: Questionnaire section present with all questions
- **WHEN** SKILL.md content is generated by `composeDesignMdSkill()`
- **THEN** the output contains a "Questionnaire" section with exactly 5 numbered questions covering product type, audience, mood, density, and reference/inspiration

#### Scenario: Dimension mapping rules defined
- **WHEN** SKILL.md content is generated
- **THEN** each question includes explicit mapping rules that convert answers to dimension values (colorTemp, lightness, density, borderRadius, tone) on a 1-5 scale

### Requirement: SKILL.md contains archetype matching algorithm
The SKILL.md SHALL include a complete archetype matching algorithm description that Claude can follow to select the best-fit template.

#### Scenario: Matching algorithm specified
- **WHEN** SKILL.md content is generated
- **THEN** the output contains a "Matching" section describing weighted Euclidean distance calculation with category bonus scoring

#### Scenario: Algorithm is deterministic and reproducible
- **WHEN** Claude follows the matching algorithm with a given dimension vector
- **THEN** the result is deterministic — same inputs always select the same archetype

### Requirement: SKILL.md contains token derivation rules
The SKILL.md SHALL include derivation rules that expand archetype anchor values into a full L2 token set (15+ semantic colors, full type scale, named spacing/radius/elevation, component tokens).

#### Scenario: Color derivation rules present
- **WHEN** SKILL.md content is generated
- **THEN** the output contains rules for deriving 15+ semantic color tokens from primary + auxiliary anchors (including success, warning, error, info, surface, background, text variants)

#### Scenario: Typography derivation rules present
- **WHEN** SKILL.md content is generated
- **THEN** the output contains rules for deriving a complete type scale (size, weight, lineHeight, letterSpacing) from baseSize + scale ratio anchors

#### Scenario: Spacing and radius derivation rules present
- **WHEN** SKILL.md content is generated
- **THEN** the output contains rules for deriving 6 named spacing levels (xs through 3xl) from the spacing unit anchor, and 6 named radius levels from the radius base anchor

#### Scenario: Component token derivation rules present
- **WHEN** SKILL.md content is generated
- **THEN** the output contains rules for defining 8-10 universal component token sets (button, input, card, etc.) using `"{category.token}"` cross-reference syntax

### Requirement: SKILL.md contains output format specification
The SKILL.md SHALL specify the exact output format for DESIGN.md: YAML front matter containing all structured tokens + Markdown body containing design philosophy narrative.

#### Scenario: YAML front matter schema defined
- **WHEN** SKILL.md content is generated
- **THEN** the output contains a complete YAML front matter schema showing required token categories (colors, typography, spacing, rounded, elevation, components, breakpoints) with their structure

#### Scenario: Markdown body structure defined
- **WHEN** SKILL.md content is generated
- **THEN** the output specifies required Markdown body sections including design philosophy, color rationale, typography rationale, and spacing/layout rationale

#### Scenario: Cross-reference syntax documented
- **WHEN** SKILL.md content is generated
- **THEN** the output documents the `"{category.token}"` cross-reference syntax for component tokens referencing design tokens

### Requirement: SKILL.md contains backup and overwrite protection
The SKILL.md SHALL instruct Claude to check for existing DESIGN.md and create a `.bak` backup before overwriting.

#### Scenario: Backup instruction present
- **WHEN** SKILL.md content is generated
- **THEN** the output contains instructions to check if DESIGN.md exists, prompt user for confirmation, and create a `.bak` backup before overwriting
