## Why

SpecFuse is a development *process*, not a stack selector. Yet the scaffolder asks the user to choose a tech stack and then specializes five generated artifacts around that choice. The stack choice is orthogonal to the pipeline's purpose: Think → Do → FuseReview → Verify works identically for Rust, React, or a bare script. Confirming a code stack during init is a decision the user's project already encodes in its own tooling — SpecFuse should not ask for it or claim to own it.

The stack layer is also the largest surface in the codebase — 15 stack profiles, a detection subsystem, a custom-stack loader, and per-stack logic threaded through six template composers — all to specialize artifacts a project will rewrite anyway. `CLAUDE.md`'s tech-stack block is a stub the user replaces; the stack-scoped `.gitignore` patterns and permission whitelists are guesses the user redoes at first commit. Removing the stack leaves the pipeline intact and the generated artifacts stack-agnostic.

## What Changes

- **BREAKING** Remove `stack` from the `ProjectConfig` interface and `TemplateContext`; delete `StackProfile` and `StackCommands` types entirely.
- **BREAKING** Remove the `--stack <id>` and `--stack-from <path>` CLI options. The `--yes` requirement that an explicit stack be supplied disappears.
- Delete the entire `src/stacks/` directory: 15 built-in profiles, `detect.ts`, `schema.ts`, `index.ts`, and `loadCustomStack`.
- Remove the stack-selection prompt, `detectAndSelect()`, `promptFullStackList()`, and the generic fallback stack from `src/prompts.ts`.
- **CLAUDE.md** (`src/templates/claude-md.ts`): delete the `## Tech Stack` block; generalize the verification commands in the apply and verify phases from `${stack.commands.test}` / `${stack.commands.lint}` to generic wording (e.g. "run the project's test command" / "run the project's linter").
- **`.gitignore`** (`src/templates/gitignore.ts`): drop per-stack `gitignorePatterns`; emit only the shared patterns (IDE, OS, env, logs). Build-output patterns are intentionally left to the model at commit time, not pre-seeded by SpecFuse.
- **`.claude/settings.local.json`** (`src/templates/claude-settings.ts`): drop per-stack `permissions`; emit only the shared permissions (git, openspec, find, rg, WebSearch).
- **`openspec/config.yaml`** (`src/templates/openspec-config.ts`): drop `stack.openspecContext` and stack-specialized `openspecRules`; emit a single stack-agnostic rule set covering only the methodological invariants (Non-goals / Trade-offs / dependency diagram / independently-testable specs / TDD task order). These rules are process concerns, not stack concerns.
- **FuseReview skill** (`src/templates/fusereview-skill.ts`): delete the `## Stack-adaptive checks` section derived from `ctx.stack.errorHandling` and `ctx.stack.concurrency`. The remaining eleven checks stand alone.
- Update `src/index.ts` CLI surface and the `scaffold()` call sites to the stack-free signatures.

## Non-goals

- **Not adding a stack-detection heuristic in place of a prompt.** SpecFuse will not guess the stack from the target directory. The project's own files declare its stack; SpecFuse has nothing to add.
- **Not moving stack profiles into the generated project.** No template, config, or skill will carry stack knowledge into the scaffolded output.
- **Not preserving the `generic` fallback stack.** The concept of a "skip / decide later" stack disappears with the stack layer.
- **Not removing the design-md archetype system.** The 16 design tokens live under `src/design-md/templates/` and are orthogonal to the stack layer.
- **Not updating `docs/samples/`.** Those are static preview pages generated by `npm run samples` from design archetypes, unrelated to stacks.
- **Not touching `openspec/changes/archive/`.** Archived changes are historical records and are never edited retroactively.
- **Not updating README.md's stack sections in this change.** The tech-stack table and custom-stack example ship as a separate `docs:` commit, keeping this change purely code (same split as the archived `remove-codegraph` change).

## Trade-offs

**Alternative 1 — Keep the stack but make it non-interactive (auto-detect).** Rejected: detection is a guess, and the user already declared the rejected premise — SpecFuse should not confirm a code stack at all. Auto-detection would keep all 15 profiles and the entire `stacks/` subsystem alive to serve a guess.

**Alternative 2 — Keep the stack prompt as an optional (default-skip) step.** Rejected: an option nobody takes is the same maintenance surface for near-zero use, and it leaves the six template composers threaded through `StackProfile` when the pipeline does not need them.

**Alternative 3 — Preserve stack-derived `.gitignore`/permission patterns as a merged "common" set.** Rejected by explicit decision: build-output patterns and stack command permissions belong to the project's own commit-time judgment. Seeding `node_modules/` for a Rust project (or cargo permissions for a JS one) is noise; leaving them out lets the model decide with full context.

**Alternative 4 — Keep stack-adaptive checks in FuseReview as generic prose.** Rejected: lifecycle and concurrency review is already covered by the eleven checks (notably the lifecycle-concurrency check). A stack-adaptive section without stack data to drive it is an empty reminder; deleting it keeps the skill self-contained and stack-free.

## Capabilities

### New Capabilities

None. Removing the stack layer is a subtraction from behavior that was never spec-governed. The specs artifact will instead document the **post-removal contract** of the scaffolded surface: that `collectProjectConfig()` asks no stack question, that `--stack`/`--stack-from` no longer exist, that generated artifacts carry no stack-specific content, and that the FuseReview skill is stack-free.

### Modified Capabilities

- `scaffold-tool-boundary`: its requirements reference stack in several places — the returned `ProjectConfig` shape lists `stack`, the questionnaire requirement names "tech stack", and non-interactive scenarios assert `--stack` is required with `--yes`. These must be revised to the stack-free contract. (This capability was created by the archived `remove-codegraph` change and synced to main specs; it now needs a delta.)
- `fusereview-skill-generation`: the requirement "Skill consumes stack profile for adaptive checks" (and its two scenarios) is removed. The requirement "Skill is self-contained and disciplined" must drop the reference to "the stack's mechanical gates."

## Verification strategy

- `npx vitest run` — full suite green with stack tests removed and remaining suites stack-free.
- `npx tsc --noEmit` — proves no residual `StackProfile`/`stack.` reference.
- `grep -riE "stack-profile|StackProfile|--stack" src/` returns no matches — the mechanical removal check.
- `npm run build && node dist/index.js --help` — CLI starts, no `--stack`/`--stack-from` options, no dangling imports.
- End-to-end scaffold: assert two prompts only (git, OpenSpec), assert generated artifacts contain no stack-derived content, assert `--yes` succeeds without `--stack`.
